# Node·Rust 공유 캐시와 데이터 표시 지연 개선

- 목표: 실행 버전을 바꿔도 마지막 quota·로컬 토큰 합계를 먼저 표시한다.
- 완료 모습: 캐시와 빠른 수집 결과가 느린 수집 완료 전에 각각 반영된다.
- 핵심 접근: 공통 실행 잠금, v2 저장 계약, 증분 토큰 집계, 작업별 독립 갱신.
- 검증: 허구 데이터의 양방향 재시작·파일 변경·실패·종료 검증과 Windows 빌드.

## 마일스톤

| 단계 | 검토 가능한 결과물 |
|---|---|
| M1 | 공통 디렉터리·quota v2·Node/Rust 상호 배제 잠금 |
| M2 | 해시 기반 토큰 인덱스와 양방향 증분 재사용 |
| M3 | 캐시 우선 표시와 quota·장애·토큰 결과별 상태 병합 |
| M4 | 후속 1회 갱신 병합·작업별 주기·종료 저장 |
| M5 | 교차 검증 기록·Windows Node/Rust 실행 산출물 |

quota 캐시 복구는 항상 stale이며 마지막 성공 시각을 유지한다. 정상 응답에서 삭제·미제공인 quota는 되살리지 않는다. 토큰은 이 PC 로그의 합계이며 quota와 서로 추정하지 않는다. Codex 5h 무한대 표시는 기존 의도대로 유지한다.

환경설정·인증·창 위치는 공유하지 않는다. 구버전 호환 계층, 설치 체계 개편과 GPUI 내부 초기화 최적화는 범위 밖이다. 실화면 최종 비교는 사용자가 수행하며 캡처는 Git 제외 경로에 둔다.

구체적인 완료 항목과 위험은 [체크리스트](SHARED_CACHE_CHECKLIST.md), 저장 계약은 [공통 계약](SHARED_CACHE_CONTRACT.md), 실행 결과와 수동 확인 방법은 [검증 기록](SHARED_CACHE_VERIFICATION.md)에 분리한다.
