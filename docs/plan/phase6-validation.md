# Phase 6 검증 기록

## 요약

이 문서는 Phase 6 인수 검토자가 자동 검사 결과와 실제 Windows에서 남은 확인 항목을 구분하는 데 사용하는 검증 참조다. 허구 계정으로 실행한 Electron 검사는 실제 계정 수집이나 Windows Narrator의 낭독 품질 검증을 대신하지 않는다. 최종 결과는 아래 항목별로 기록한다.

## 자동 검사

- 검증일: 2026-09-02
- 대상: Windows x64 packaged Electron 앱, 허구 계정과 격리된 테스트 userData
- Step 6.1: Guard·typecheck·lint·Electron E2E 8개 통과. 추가 quota의 Enter/Space 토글, refresh 중 펼침 유지, 새 실행 기본 접힘, 전체 계정 도움말과 목록 스크롤을 확인했다.
- Step 6.2: Guard·typecheck·lint·단위/통합 107개·Electron E2E 10개 통과. 미제공 quota·cache, stale 오류, reset 경과 설명과 provider 요청 없는 30초 카운트다운을 확인했다.
- Step 6.3: Guard·typecheck·lint·단위/통합 107개·Electron E2E 13개 통과. 다크/라이트와 100%/150% 배율의 긴 내용·오류 화면, 텍스트 대비·focus·툴팁 폭을 검사했다. 실제 Electron 키 입력의 Escape hide/reopen 후 툴팁이 남지 않음을 확인했으며, renderer blur를 강제로 발생시키는 보조 코드는 사용하지 않았다.
- Step 6.4: Guard·typecheck·lint·단위/통합 120개·packaged Electron E2E 13개 통과. 메뉴를 열 때 자동 시작의 실제 설정을 읽고, 설정·readback 예외를 처리하는 경로를 fake로 검증했다. 실제 앱이 사용하는 Quit 핸들러의 반복 요청·지연된 정리, 진행 중 polling의 종료 대기·실패 후 재예약, cache flush도 검증했다.
- 최종 검사: Guard, typecheck, lint, 단위/통합 23개 파일·120개 테스트, packaged Electron 13개 테스트, `git diff --check`, staged diff 전체 검토와 gitleaks 통과. 공개 IPC·snapshot 계약, provider 인증·파서, 로컬 집계 알고리즘과 의존성 변경은 없다.
- CSS는 Guard 범위 밖이므로 diff와 스크린샷을 별도로 검토했다. 배율은 packaged Electron의 `--force-device-scale-factor=1`·`1.5`, 테마는 `emulateMedia`로 검사했다. 이는 실제 Windows 배율 설정 변경·서로 다른 배율 모니터 이동을 대체하지 않는다.
- 위치 계산 단위 테스트는 상·하·좌·우 작업표시줄, 유효하지 않은 bounds, 제거된 모니터, 음수 좌표를 다룬다. work area 자체가 420×320보다 작으면 창을 축소하지 않고 해당 영역의 시작점에 맞춘다. 이 특수 환경에서 창 전체가 들어간다고 보장하지 않는다.
- 패키지 빌드는 성공했으며 기존 Forge/Vite의 `inlineDynamicImports` 폐기 예정 경고는 남아 있다. 의존성 갱신은 이번 Phase에 포함하지 않았다.

## 재현과 화면 산출물

### 후속 보완 — 도움말 발견성과 하단 가림

2026-09-02 사용자 피드백에 따라 하단에 `? 도움말`과 `Tab 이동 · Enter 실행 · Esc 숨김`을 추가했다. 도움말은 Windows 자동 테마, Tab·Shift+Tab·Enter·Space, 팝오버 숨김과 트레이 메뉴를 설명하며 README에도 별도 조회 표를 둔다.

툴팁은 고정된 오른쪽 아래 위치 대신 대상과 실제 내용 높이를 기준으로 배치한다. 하단 안내 영역과 겹치거나 화면을 벗어나면 위로 표시하고, 다른 설명 버튼을 덮을 때도 위쪽 공간이 충분하면 위를 선택한다. 목록 스크롤로 대상이 가려지면 해당 툴팁을 닫는다.

회귀 검사 중 reset 툴팁이 cache read 버튼을 덮는 문제가 확인돼 버튼 간 충돌도 처리했다. 기존 hover 테스트를 유지한 반복 검사와 최종 Guard·typecheck·lint·단위/통합 125개·packaged Electron 13개를 통과했다. 다크·라이트 × 100%·150%에서 하단 토큰 툴팁의 아래끝이 대상과 앱 하단 안내보다 위에 있는지 실제 DOM 좌표로 검사했다. 아래 수동 확인 대기는 그대로 유지한다.

### 후속 보완 — 팝오버 폭과 스크롤바

2026-09-02 사용자 피드백에 따라 팝오버 폭을 420px에서 480px로 넓혔다. 높이 320px와 110% 글꼴은 유지한다. 위의 이전 단계 기록은 당시 420px 검증 결과이며, 현재 창 배치에는 480×320 크기가 적용된다.

목록과 툴팁은 8px 너비의 기본 Chromium 스크롤바를 사용한다. 손잡이와 트랙은 다크·라이트 테마 색상을 따르고, 손잡이에 마우스를 올리면 더 선명해진다. 목록에는 스크롤바 공간을 미리 확보해 내용 폭의 변화를 줄였다.

Guard·typecheck·lint·단위/통합 125개·packaged Electron 13개를 통과했다. 다크·라이트 × 100%·150%에서 스크롤바의 너비·테마 색상, 실제 목록 스크롤과 가로 넘침 부재를 검사하고 기존 하단 툴팁 검사를 유지했다. 기본 다크·라이트 캡처도 시각 검토했다. 실제 혼합 배율 모니터와 Narrator 등 아래 수동 확인 대기는 그대로 유지한다.

### 후속 보완 — 기본 화면 무스크롤과 reserve 표시 제외

2026-09-02 추가 피드백에 따라 현재 크기를 480×360으로 조정했다. 기본 다크·라이트 × 100%·150% 화면에서 문서와 provider 목록의 가로·세로 넘침이 없고 두 provider의 footer가 모두 보이는지 검사했다. 추가 한도를 펼친 긴 목록은 계속 스크롤되며, 오른쪽 텍스트와 스크롤 트랙 사이에 8px 여백을 두었다(실제 좌표 검사에서 최소 7px).

Codex의 `model_weekly` 중 공백 제거·대소문자 정규화 후 이름이 `gpt-reserve Weekly`와 정확히 일치하는 항목만 추가 목록과 개수에서 제외한다. fake snapshot에는 해당 항목을 남겨 원본 보존과 UI 제외를 함께 검사했다. provider 수집·인증 방식은 변경하지 않았다.

Guard·typecheck·lint·단위/통합 125개·packaged Electron 13개를 통과했다. 스크롤바 기본 색상 검사는 포인터를 헤더로 옮겨 의도치 않은 hover 상태를 제거했고, 기존 색상 검증 조건은 유지했다. 기본 화면과 펼친 화면을 시각 검토했으며 아래 수동 확인 대기는 유지한다.

### 후속 보완 — 토큰 표시와 실행 중 테마 전환

2026-09-03 사용자 요청에 따라 하단 버튼과 앱 창 전용 단축키를 추가했다. `Ctrl+Shift+T`는 로컬 토큰 표시를, `Ctrl+Shift+L`은 밝은·어두운 테마를 전환한다. 토큰 숨김은 수집 중단이 아니며 quota·토큰 집계는 계속된다. 표시 선택은 새로고침·팝오버 숨김 뒤에도 유지하지만 저장하지 않는다. 앱을 다시 시작하면 토큰 표시 켜짐과 OS 자동 테마로 돌아온다.

창 크기 변경은 strict Boolean 입력의 `setTokensVisible` IPC로 제한한다. main이 정한 크기만 사용하며 renderer는 임의의 좌표·크기를 전달할 수 없다. sender·payload 검증과 handler 정리를 유지하고, resize 뒤 현재 창 크기로 트레이 위치를 다시 계산한다. 진행 중인 표시 요청은 중복 실행하지 않으며 실패 시 기존 표시를 유지하고 quota 오류와 별도로 안내한다. provider·인증·토큰 집계 알고리즘과 사용량 게이지는 변경하지 않았다.

축소 화면은 문서 전체 높이뿐 아니라 provider 목록의 실제 scroll/client 크기, 각 provider의 마지막 줄과 하단 버튼 위치를 검사한다. native resize와 React의 토큰 제거 완료 시점이 다르므로 두 전환이 끝난 뒤 측정한다. 아래 수동 확인 대기는 그대로 유지한다.

최종 크기는 토큰 표시 시 480×360, 숨김 시 480×304다. Guard·typecheck·lint·단위/통합 128개·packaged Electron 14개를 통과했다. 다크·라이트 × 100%·150% 축소 화면은 전환 완료 후 스크롤과 잘림이 없음을 검사했고, 별도 매트릭스 3회 반복도 통과했다. 버튼·단축키 전환, 새로고침·창 숨김/재표시 뒤 선택 유지, 수동 테마의 OS 변경 독립성, 반복 키·IME 조합·입력 요소에서의 단축키 무시를 확인했다. 100% 라이트와 150% 다크 축소 캡처를 시각 검토했으며 `git diff --check`와 변경분 gitleaks 검사도 통과했다. 커밋·병합은 하지 않았다.

축소 캡처는 `test-results/`의 `tui-<theme>-<scale>-compact.png`와 기본 흐름의 `tui-compact-dark.png`·`tui-compact-light.png`에 생성한다. 모두 허구 계정 데이터다.

### 후속 보완 — 이모지 토글과 하단 정렬

2026-09-03 토큰·테마 텍스트 버튼을 🪙·🌙/☀️ 이모지로 바꾸고 하단 Help와 단축키 안내를 영어로 통일했다. 토큰 off만 회색·취소선으로 구분하며 테마는 현재 상태의 아이콘을 사용한다. 각 버튼의 접근성 이름·pressed 상태·단축키와 마우스 도움말을 유지한다. 버튼 그룹은 왼쪽, 단축키는 오른쪽에 두고 범위 안내와 양 끝을 맞췄다. 창 크기·IPC·집계·게이지는 바꾸지 않았다.

실행 중인 개발 서버와 공유하는 빌드 출력을 덮어쓰지 않기 위해 이번에는 패키지를 새로 만들지 않았다. `LLM_USAGE_MONITOR_E2E_DEV=1`을 설정한 별도 검사 프로세스에서 현재 개발 진입점과 허구 계정으로 Electron 14개 검사를 통과했다. 기본 검사 경로는 기존 패키지 그대로다. Guard·typecheck·lint·단위/통합 128개·diff·민감정보 검사도 통과했고 100% 다크와 150% 라이트 축소 화면을 시각 검토했다.

현재 개발 환경의 150% 배율에서는 native content와 renderer 폭이 모두 482px로 보고되는 경우를 반복 확인했다. 정확한 환경별 원인은 확정하지 않았으며 production 크기 설정은 변경하지 않았다. 테스트는 100%의 480px 기대값을 유지하고 150%만 기존 높이 허용 범위처럼 폭 480~484px를 허용하되 native/renderer 폭 일치, 목록 넘침 부재와 하단 정렬을 함께 검사한다. 커밋·병합과 아래 수동 인수는 진행하지 않았다.

### 실행과 캡처

저장소 루트에서 `corepack pnpm typecheck`, `corepack pnpm lint`, `corepack pnpm test`, `corepack pnpm test:e2e`를 실행한다. E2E는 x64 앱을 패키징한 뒤 허구 계정과 격리된 userData로 실행하며 실제 vendor 계정·인증을 사용하지 않는다.

마지막 명령은 Git에 포함하지 않는 `test-results/` 아래에 기본 다크·라이트 × 1·1.5 배율의 `tui-<theme>-<scale>-normal.png`, 추가 quota·오류의 다크·라이트 × 1·1.5 배율 화면을 생성한다. 기본 화면, 긴 모델명, 큰 토큰 수치, 설명 툴팁과 목록 스크롤을 확인할 수 있다. 스크린샷은 회귀 검사 산출물이지 실제 계정의 사용량 증빙이 아니다.

후속 보완 화면은 같은 출력 폴더의 `tui-<theme>-<scale>-normal-help.png`와 각 배율의 `footer-help`·`claude-tooltip` 스크린샷으로 확인한다.

## 수동 확인 대기

아래 항목은 자동 테스트의 이벤트 호출이나 스크린샷으로 완료 처리하지 않는다. 현재 도구에서는 네이티브 Windows UI 조작과 Narrator 청취를 수행할 수 없어 미검증으로 남긴다.

- [ ] Windows Narrator: 핵심 quota 이름·사용률·상태, 토큰 설명, 추가 quota 버튼의 접힘 상태를 읽으며 주기 갱신 시 전체 목록을 반복 낭독하지 않는다.
- [ ] 네이티브 트레이: 실제 아이콘 클릭·우클릭과 키보드 메뉴 탐색으로 열기·새로고침·종료를 실행할 수 있다.
- [ ] 자동 시작: 원래 설정을 기록한 뒤 메뉴에서 opt-in을 변경하고 다시 열어 체크 상태를 확인한다. 검증 후 반드시 원래 설정으로 복원한다.
- [ ] 실제 혼합 배율·멀티 모니터: 각 모니터에서 열기, 모니터 분리 후 재표시 시 work area 안에 창이 보인다.

사용자가 직접 확인한 결과와 환경을 이 문서에 추가하기 전에는 Phase 6 전체 인수를 완료로 표시하지 않는다. 설치·업그레이드·제거 최종 검증은 Phase 7의 별도 관문이다.

2026-09-03 사용자 요청으로 후속 UI 변경을 `0d6081d` (`feat(ui): 표시 토글과 트레이 가독성 마감`)에 커밋했다. 직전 Guard·typecheck·lint·단위/통합 128개·개발 Electron 14개와 staged diff·gitleaks 검사를 다시 통과했다. 위의 커밋 전 기록은 당시 상태다.

Phase 6은 `feat/phase-6-tui-polish`에 보존하며 수동 인수와 `main` 병합은 아직 수행하지 않았다. 같은 날 사용자 요청에 따라 Antigravity 검토를 재개했다. 기존 보류 순서는 [재개 계획](phase5-5-antigravity.md)으로 대체하며 Phase 6 수동 인수나 Phase 7 설치 검증을 완료로 간주하지 않는다.
